---

push前に以下を確認する。

- git status(未コミット・未追跡ファイルの有無)
- 現在のbranch
- git diff / git diff --cached(意図しない変更が含まれていないか)
- push対象のコミット一覧(ローカルとorigin/mainの差分)
- 意図的な未コミット変更(例: ローカル開発用のLAN-IP設定等)が
  push対象に含まれていないか

## 注意

- この確認自体ではpushしない。確認結果を報告し、ユーザーからの
  明示的な指示を待ってからpushする
- 問題が見つかった場合は、憶測で修正せず、まず状況を報告する

## 複数リポジトリ(バックエンド/iOS/Android)を跨ぐ変更の場合

- 依存関係のある変更(例: APIのwire format変更)は、依存元(通常は
  バックエンド)を先にpushすると、まだ追従していない依存先
  (iOS/Android)が壊れる可能性がある。各リポジトリのpush前確認を
  それぞれ行った上で、バックエンド→iOS→Androidのように連続して
  pushし、片方だけ新仕様になっている時間を最小化する
- 前のリポジトリのpush・CI成功を確認してから次のリポジトリへ進む
